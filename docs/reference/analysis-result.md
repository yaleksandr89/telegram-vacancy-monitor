# Формат оценки и уведомлений

Приложение получает от модели структурированную оценку, сохраняет её и формирует отдельное текстовое уведомление для Телеграмма. JSON модели и сообщение пользователю имеют разные форматы.

## Ответ API и JSON модели

[`OpenAiCompatibleEvaluator`](../../src/Analysis/OpenAiCompatibleEvaluator.php) принимает непотоковый ответ Chat Completions: первый элемент `choices`, внутри него `message.content` строкового типа. В этой строке должен быть ровно один JSON-объект. Непустые `tool_calls` и любое ненулевое `function_call` отклоняются; вызовы инструментов не выполняются.

[Метод `EvaluationPromptBuilder::build()`](../../src/Analysis/EvaluationPromptBuilder.php) включает схему в системное сообщение вместе с вашими инструкциями. Профиль и недоверенный текст вакансии передаются в пользовательском сообщении, без отдельной передачи метаданных чата.

Все поля ниже обязательны, дополнительные поля запрещены. Структуру задаёт [`AnalysisResult::jsonSchema()`](../../src/Analysis/AnalysisResult.php), фактическую проверку выполняет [`AnalysisResultValidator::validate()`](../../src/Analysis/AnalysisResultValidator.php).

| Поле | Тип и допустимое значение | Смысл |
| --- | --- | --- |
| `company` | Непустая строка | Компания либо указание, что она не названа |
| `position` | Непустая строка | Должность |
| `verdict` | `apply`, `borderline`, `skip` | Решение о целесообразности отклика |
| `priority` | `high`, `medium`, `low` | Приоритет рассмотрения |
| `matches` | Массив непустых строк, может быть пустым | Совпадения требований с профилем |
| `risks` | Массив непустых строк, может быть пустым | Риски и существенные расхождения |
| `geography` | Непустая строка | География и формат работы |
| `pay` | Непустая строка | Оплата или отсутствие данных о ней |
| `missing` | Массив непустых строк, может быть пустым | Вопросы и недостающие сведения |
| `rationale` | Непустая строка | Краткое обоснование |
| `source_status` | Только `unavailable` в ответе модели | Модель не подтверждает происхождение публикации |

Строки должны быть корректным UTF-8 и содержать видимый текст. Валидатор отклоняет управляющие символы, невидимое форматирование, разделители строк, HTTP/HTTPS-ссылки и конструкции вида HTML-тегов. Переводы строк внутри строковых значений также не подходят. Используйте отдельные элементы массивов для отдельных пунктов. Внешнее обрамление допускается только одним Markdown-блоком с пометкой `json`: адаптер снимает его до строгой проверки объекта. Дополнительный текст, другие блоки и разметка отклоняются.

Ниже **искусственный шаблон объекта внутри `message.content`** с условными значениями полей.

```json
{
  "company": "Компания из объявления",
  "position": "Должность из объявления",
  "verdict": "borderline",
  "priority": "medium",
  "matches": ["Подтверждённое совпадение"],
  "risks": [],
  "geography": "Формат и география из объявления",
  "pay": "Не указана",
  "missing": ["Условие, которое нужно уточнить"],
  "rationale": "Краткое объяснение на основе профиля и вакансии",
  "source_status": "unavailable"
}
```

Для HTTP-ответа этот объект должен быть закодирован **строкой** в `choices[0].message.content`, а не вложен туда как объект. Полный ответ API ограничен 65 536 байтами. Некорректная оболочка или JSON допускают повтор в пределах `AI_MAX_ATTEMPTS`.

## Вердикт и приоритет

Значения перечислены в [`Verdict`](../../src/Analysis/Verdict.php) и [`Priority`](../../src/Analysis/Priority.php), русские подписи задаёт [`VacancyResultFormatter::format()`](../../src/Application/VacancyResultFormatter.php).

| Значение | Текст в Телеграмме | Как читать |
| --- | --- | --- |
| `apply` | Откликаться | Предложение стоит рассмотреть для отклика |
| `borderline` | Погранично | Есть сомнения или существенные вопросы для уточнения |
| `skip` | Пропустить | Предложение не стоит рассматривать по заданным критериям |
| `high` | высокий | Высокий приоритет |
| `medium` | средний | Средний приоритет |
| `low` | низкий | Низкий приоритет |

Приложение проверяет допустимые значения, но не задаёт числовой порог и не требует определённого сочетания вердикта и приоритета. Смысловые критерии задаёте вы в `instructions.md`; **решение принимает модель**. Вердикт не отправляет отклик работодателю.

## Уведомление в Телеграмме

[Форматтер](../../src/Application/VacancyResultFormatter.php) собирает обычное текстовое сообщение. Ниже шаблон расположения строк с условными подстановками, без реального результата:

```text
Откликаться / Погранично / Пропустить
Приоритет: высокий / средний / низкий
{компания} — {должность}
{краткое обоснование}
География и формат: {география и формат}
Оплата: {оплата}
Совпадения: {пункты через точку с запятой}
Риски: {пункты через точку с запятой}
Уточнить: {пункты через точку с запятой}
Источник: {ссылка с пометкой или «ссылка недоступна»}
Сообщение в чате: {ID входящего сообщения}
```

Пустые списки «Совпадения», «Риски» и «Уточнить» опускаются. ID в последней строке относится к вашему входящему сообщению в чате с ботом, а не к исходной публикации в канале.

Если полный ответ превышает лимит 4096 единиц UTF-16, он сокращается с пометкой `(сокращено для Telegram)`. Компания, позиция и обоснование получают отдельные подписи; вердикт, приоритет и источник сохраняются. Эмодзи учитываются без разрезания символов. Полная оценка остаётся в SQLite.

## Источник и его достоверность

Ссылки берутся из текста вакансии, а не из ответа модели. Приложение не открывает сайты и не загружает страницы.

- Если допустимой ссылки нет, показывается «Источник: ссылка недоступна».
- Для найденной HTTP/HTTPS-ссылки — «ссылка из объявления (не проверена)».
- Для уже имеющейся ссылки вида `https://t.me/c/…/…`, чьи числовые ID совпадают с данными пересылки из канала, — «совпадает с ID пересланной публикации».

Точная проверка и отбор ссылок находятся в [`sourceDescription()` и `verifiedSource()`](../../src/Application/VacancyResultFormatter.php). Совпадение ID подтверждает связь ссылки с пересылкой, а не правдивость вакансии или надёжность работодателя. Адрес по одним метаданным не создаётся.

В ответе модели `source_status` всегда равен `unavailable`. При сохранении [`AnalysisResult::toJson()`](../../src/Analysis/AnalysisResult.php) приложение само устанавливает `verified_origin_ids`, если подтверждено описанное совпадение ссылки и ID; иначе сохраняет `unavailable`. Модель не может назначить себе подтверждённый статус.

## Сообщения о ходе обработки

Приём и обработку разделяют [`IncomingUpdateProcessor`](../../src/Application/IncomingUpdateProcessor.php) и [`VacancyAnalysisPipeline`](../../src/Application/VacancyAnalysisPipeline.php).

| Событие | Сообщение или состояние |
| --- | --- |
| Новая вакансия сохранена | «Вакансия сохранена.» |
| Известная публикация отправлена снова | «Эта публикация уже сохранена.» |
| Начало AI-запроса | «Вакансия передана на анализ ИИ. Результат придёт сюда, как только анализ завершится.» |
| Отказ точного предфильтра | «Пропустить» и причина точного совпадения; без AI-оценки и уведомления начала |
| Окончательная ошибка анализа | «Не удалось обработать» и «Техническая ошибка анализа. Исходная вакансия сохранена.»; затем источник и ID сообщения |
| Окончательная ошибка доставки | `delivery_status = failed` в SQLite; отдельное сообщение о неудаче доставки не отправляется |

## Как проходит обработка

1. **Сохранение.** Приложение записывает вакансию и задание в SQLite. После успешной записи бот отправляет «Вакансия сохранена.». Если Телеграмм повторно доставит то же обновление, новая вакансия не создаётся.
2. **Начало анализа.** Бот пытается отправить сообщение о начале работы. Для этого уведомления предусмотрена одна попытка; даже если оно не дошло, анализ продолжается.
3. **Оценка.** Модель сопоставляет вакансию с профилем и инструкциями. Готовая оценка сохраняется в SQLite **до** отправки результата в Телеграмм.
4. **Отправка.** Бот отправляет сохранённый результат. Если при доставке возникла временная ошибка, приложение может повторить отправку, **не вызывая модель заново**.
5. **Возобновление.** После перезапуска приложение продолжает незавершённые задания с учётом уже использованных попыток. Если попытки исчерпаны, задание само по себе не запускается заново.

При сбое связи в момент отправки Телеграмм мог получить сообщение, а приложение — не получить подтверждение. В таком случае итог может прийти повторно. Подробнее о повторах, курсоре и сохранении — в [разборе процесса получения вакансий](../guides/message-processing.md). Реализация обработки — [`VacancyAnalysisPipeline`](../../src/Application/VacancyAnalysisPipeline.php).
