The application receives a structured assessment from the model, saves it, and produces a separate text notification for Telegram. The model JSON and the user-facing message have different formats.

## API response and model JSON

[`OpenAiCompatibleEvaluator`](../../../src/Analysis/OpenAiCompatibleEvaluator.php) accepts a nonstreaming Chat Completions response: the first `choices` item must contain `message.content` as a string. That string must contain exactly one JSON object. Nonempty `tool_calls` and any nonnull `function_call` are rejected; tools are never executed.

[`EvaluationPromptBuilder::build()`](../../../src/Analysis/EvaluationPromptBuilder.php) includes the schema in the system message with your instructions. The profile and untrusted vacancy text are passed in a user message, without separately sending chat metadata.

All fields below are required; extra fields are forbidden. [`AnalysisResult::jsonSchema()`](../../../src/Analysis/AnalysisResult.php) defines the structure and [`AnalysisResultValidator::validate()`](../../../src/Analysis/AnalysisResultValidator.php) performs validation.

| Field | Type and allowed values | Meaning |
| --- | --- | --- |
| `company` | Nonempty string | Company, or indication that it was not named. |
| `position` | Nonempty string | Job title. |
| `verdict` | `apply`, `borderline`, `skip` | Whether applying is worthwhile. |
| `priority` | `high`, `medium`, `low` | Review priority. |
| `matches` | Array of nonempty strings; may be empty | Requirements matching the candidate profile. |
| `risks` | Array of nonempty strings; may be empty | Risks and material mismatches. |
| `geography` | Nonempty string | Location and work arrangement. |
| `pay` | Nonempty string | Compensation or information that it was not specified. |
| `missing` | Array of nonempty strings; may be empty | Questions and missing information. |
| `rationale` | Nonempty string | Brief reasoning. |
| `source_status` | Only `unavailable` in model output | The model does not verify the publication's origin. |

Strings must be valid UTF-8 and contain visible text. The validator rejects control characters, invisible formatting, line separators, HTTP/HTTPS links, and HTML-like tags. Newline characters inside string values are not accepted; use separate array elements for separate points. The only permitted outer wrapper is one Markdown fenced block labeled exactly `json`, which the adapter strips before strict validation. Additional text, other code blocks, and formatting are rejected.

Below is a **synthetic object template within `message.content`**, with placeholder values retained in Russian to match the example scenario:

```json
{
  "company": "Компания из объявления",
  "position": "Должность из объявления",
  "verdict": "borderline",
  "priority": "medium",
  "matches": ["Подтверждённое совпадение"],
  "risks": [],
  "geography": "Формат и география из объявления",
  "pay": "Не указана",
  "missing": ["Условие, которое нужно уточнить"],
  "rationale": "Краткое объяснение на основе профиля и вакансии",
  "source_status": "unavailable"
}
```

In the HTTP response, this object must be encoded as a **string** in `choices[0].message.content`, not nested there as an object. The full API response is limited to 65,536 bytes. An invalid response envelope or JSON may be retried within `AI_MAX_ATTEMPTS`.

## Verdict and priority

Valid values are defined by [`Verdict`](../../../src/Analysis/Verdict.php) and [`Priority`](../../../src/Analysis/Priority.php); Russian labels are generated by [`VacancyResultFormatter::format()`](../../../src/Application/VacancyResultFormatter.php).

| Value | Telegram text (Russian) | Meaning |
| --- | --- | --- |
| `apply` | Откликаться | Consider applying. |
| `borderline` | Погранично | There are doubts or material points needing clarification. |
| `skip` | Пропустить | Do not consider the offer under the chosen criteria. |
| `high` | высокий | High priority. |
| `medium` | средний | Medium priority. |
| `low` | низкий | Low priority. |

The application validates allowed values but does not impose a numeric threshold or prescribe a particular verdict/priority combination. You define the substantive criteria in `instructions.md`; **the model makes the decision**. A verdict does not send an application to the employer.

## Telegram notification

The [formatter](../../../src/Application/VacancyResultFormatter.php) assembles a plain-text message. Below is a schematic layout with placeholders, **not an actual result**. The output labels are Russian because the application uses Russian user-facing messages:

```text
Откликаться / Погранично / Пропустить
Приоритет: высокий / средний / низкий
{компания} — {должность}
{краткое обоснование}
География и формат: {география и формат}
Оплата: {оплата}
Совпадения: {пункты через точку с запятой}
Риски: {пункты через точку с запятой}
Уточнить: {пункты через точку с запятой}
Источник: {ссылка с пометкой или «ссылка недоступна»}
Сообщение в чате: {ID входящего сообщения}
```

Empty `matches`, `risks`, and `missing` lists are omitted. The last line's ID refers to your incoming message in the bot chat, not the original publication in a channel.

If the full message exceeds 4,096 UTF-16 code units, it is shortened with the marker `(сокращено для Telegram)`. Company, position, and rationale receive their own labels; verdict, priority, and source are preserved. Emoji are handled without splitting characters. The full assessment remains in SQLite.

## Source and its reliability

Links come from vacancy text, not the model response. The application does not open websites or download pages.

- If no acceptable URL is found, it displays `Источник: ссылка недоступна` (“Source: link unavailable”).
- For a found HTTP/HTTPS URL, it displays `ссылка из объявления (не проверена)` (“link from the advertisement, unverified”).
- For an existing URL of the form `https://t.me/c/…/…` whose numeric IDs match the forwarded channel publication metadata, it displays `совпадает с ID пересланной публикации` (“matches the forwarded publication ID”).

The exact selection and validation are in [`sourceDescription()` and `verifiedSource()`](../../../src/Application/VacancyResultFormatter.php). Matching IDs confirm that a link belongs to the forwarded publication, **not** that the vacancy is truthful or the employer trustworthy. No URL is constructed from metadata alone.

The model must always return `source_status = "unavailable"`. When persisting [`AnalysisResult::toJson()`](../../../src/Analysis/AnalysisResult.php), the application sets `verified_origin_ids` itself if the described URL/ID match is confirmed; otherwise it retains `unavailable`. The model cannot claim verified status on its own.

## Processing notifications

Reception and processing are separated between [`IncomingUpdateProcessor`](../../../src/Application/IncomingUpdateProcessor.php) and [`VacancyAnalysisPipeline`](../../../src/Application/VacancyAnalysisPipeline.php).

| Event | Message or state |
| --- | --- |
| New vacancy saved | `Вакансия сохранена.` |
| Known publication sent again | `Эта публикация уже сохранена.` |
| AI request started | `Вакансия передана на анализ ИИ. Результат придёт сюда, как только анализ завершится.` |
| Exact prefilter rejection | `Пропустить` and the exact-match reason, with no AI assessment or start notification. |
| Final analysis error | `Не удалось обработать` and `Техническая ошибка анализа. Исходная вакансия сохранена.`, followed by the source and message ID. |
| Final delivery error | `delivery_status = failed` in SQLite; no separate delivery-failure message is sent. |

## Processing steps

1. **Save.** The application stores the vacancy and job in SQLite. After the write succeeds, the bot sends `Вакансия сохранена.`. Repeated delivery of the same update does not create another vacancy.
2. **Start analysis.** The bot attempts to send a start notification once. Even if that notification is lost, analysis continues.
3. **Assess.** The model compares the vacancy with the profile and instructions. The completed assessment is stored in SQLite **before** sending the result to Telegram.
4. **Deliver.** The bot sends the saved result. If a temporary delivery error occurs, it can retry **without invoking the model again**.
5. **Resume.** After restart, unfinished jobs continue with the already consumed attempts accounted for. Exhausted jobs are not restarted automatically.

If a network failure occurs while sending, Telegram may receive the message even when the application never receives confirmation; the result can then be delivered again. Details about retries, cursor, and persistence are in the [vacancy processing guide](message-processing.md). Processing is implemented by [`VacancyAnalysisPipeline`](../../../src/Application/VacancyAnalysisPipeline.php).
