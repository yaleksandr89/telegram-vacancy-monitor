Сервер принимает вакансии через HTTPS, сохраняет их в SQLite и обрабатывает по расписанию. Текст вакансии можно отправить боту или переслать из другого чата.

[`public/webhook.php`](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/public/webhook.php) сохраняет входящие сообщения. Оценку ИИ и отправку результатов запускает `php bin/bot.php work-once`. Для одного токена выбирайте либо этот режим, либо локальный polling.

## Подготовьте среду

Разместите файлы репозитория в постоянном каталоге на сервере вне публичной директории сайта.

Нужны PHP `^8.5` для CLI и PHP-FPM, Composer, HTTPS с действительным сертификатом и расширения `curl`, `json`, `mbstring`, `PDO`, `pdo_sqlite`. Проверьте расширения отдельно для CLI и FPM: их настройки могут различаться. Требования заданы в [`composer.json`](../../composer.json).

Из корня серверной установки выполните:

```bash
# Установите зависимости по composer.lock из корня проекта.
composer install
```

Используйте `composer.lock` проекта. Composer нужен для подготовки установки, а не для обработки запросов.

Настройте HTTP-сервер и выделенный пул PHP-FPM средствами вашей системы:

- DocumentRoot указывает строго на `public/`; единственная публичная PHP-точка — `/webhook.php`.
- Запретите листинг каталогов, выполнение других PHP-путей и переходы через псевдонимы каталогов или резервный маршрут в корень проекта.
- `config/`, `vendor/`, `var/`, `.git/` и исходники недоступны по HTTP.
- Ограничьте тело запроса 256 КиБ; приложение также проверяет этот предел.
- У FPM отключён `display_errors`. Тела запросов, токены, секретный заголовок и тексты вакансий не записываются в HTTP-журналы.

Конкретные директивы зависят от вашего HTTP-сервера. До регистрации webhook проверьте HTTPS и недоступность приватных путей извне.

## Создайте конфигурацию и профиль

Если `config/bot.ini` ещё не существует, скопируйте [образец](../../config/bot.example.ini). Редактируйте файл в редакторе, не вводя токены в команды.

1. Создайте бота через [BotFather](https://t.me/BotFather), сохраните его токен в `TELEGRAM_BOT_TOKEN`.
2. Пока выбран `polling` и webhook не зарегистрирован, отправьте боту `/start` и выполните `php bin/bot.php identify`. Если `var/bot.lock` занят, сначала остановите другой polling-процесс.
3. Укажите свой ID в `TELEGRAM_ALLOWED_USER_ID`.
4. Подготовьте `config/profile/local/candidate.md` и `config/profile/local/instructions.md` по [руководству профиля](../../config/profile/README.md).
5. Настройте `AI_PROVIDER_LOCATION`, `AI_BASE_URL`, `AI_MODEL` и при необходимости `AI_API_KEY`. Подключение и передачу данных описывает [руководство моделей](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/docs/guides/ai-models.md).

Для сервера модели на том же VDS допустим адрес `http://127.0.0.1:1234/v1` с режимом `local`. Если модель работает на другом компьютере, укажите доступный с VDS частный IPv4. Облачный режим требует HTTPS и ключа.

После определения ID переключите настройки:

```ini
; Включите webhook, затем замените пустой секрет сгенерированным.
TELEGRAM_RECEIVE_MODE = "webhook"
TELEGRAM_WEBHOOK_SECRET = ""
```

Пустой секрет выше замените случайным значением длиной 1–256 символов из `A–Z`, `a–z`, `0–9`, `_`, `-`. Например, сгенерируйте 64-символьный секрет штатным PHP:

```bash
# Команда генерирует секрет, но не содержит его в истории терминала.
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

Скопируйте выведенную строку в `TELEGRAM_WEBHOOK_SECRET` приватного `config/bot.ini` и не публикуйте её в логах или снимках экрана. Команда `webhook set` сама передаст секрет в Telegram как `secret_token`; не добавляйте его в URL.

Полный перечень параметров — в [справочнике конфигурации](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/docs/reference/configuration.md).

## Настройте права и подготовьте SQLite

CLI и FPM должны использовать один абсолютный путь установки и одну БД `var/vacancies.sqlite`. Удобнее выделить отдельного непривилегированного пользователя приложения для cron и пула PHP-FPM.

Ему нужны чтение кода, `vendor/`, INI и профиля, запись в БД и каталог `var/`: SQLite создаёт рядом журнал, а CLI — `bot.lock`. Остальным пользователям доступ к конфигурации и данным не выдавайте. Если пользователи CLI и FPM различаются, настройте точечные ACL, в том числе наследуемые для новых файлов. CLI/FPM используют `umask(0077)`, поэтому одной общей группы недостаточно.

Проверьте права от обеих учётных записей. Не применяйте широкие рекурсивные `chown` или `chmod` ко всему проекту.

До регистрации webhook запустите от пользователя cron:

```bash
# Создаёт схему БД и может обработать ожидающие задания (не dry-run).
php bin/bot.php work-once
```

Используйте PHP CLI нужной версии. Команда проверяет настройки и профиль, создаёт `var/` и схему БД при необходимости, а также обрабатывает уже ожидающие задания. Вебхук принимает сообщения после создания БД.

Перед обновлением сделайте закрытую резервную копию INI, профиля и SQLite при остановленных обработчиках. Не заменяйте существующую БД пустой и не удаляйте состояние очереди ради проверки.

## Зарегистрируйте webhook

Убедитесь, что HTTPS-адрес `/webhook.php` доступен для запросов Телеграмма. Запрос без секретного заголовка получает HTTP 403, а GET — HTTP 405. До регистрации остановите любые процессы `run` и `identify` этого бота: одновременно использовать polling и webhook нельзя.

В установке из исходников используйте штатные команды `php bin/bot.php webhook`. Они читают токен и, когда нужен, секрет из приватного `config/bot.ini`; вводить секреты в терминал не требуется.

| Команда | Назначение |
| --- | --- |
| `php bin/bot.php webhook set <https-url>` | Регистрация webhook по заданному HTTPS-адресу; требует режима `webhook` и корректного секрета в INI |
| `php bin/bot.php webhook info` | Состояние регистрации, число ожидающих обновлений и сведения о последней ошибке доставки |
| `php bin/bot.php webhook delete` | Снятие регистрации без удаления ожидающих обновлений |

Реализация вызывает официальные методы [setWebhook](https://core.telegram.org/bots/api#setwebhook), [getWebhookInfo](https://core.telegram.org/bots/api#getwebhookinfo) и [deleteWebhook](https://core.telegram.org/bots/api#deletewebhook). При регистрации используются `allowed_updates=["message"]`, `drop_pending_updates=false` и `max_connections=1`. При удалении также используется `drop_pending_updates=false`.

### Управление вебхуком

После настройки `TELEGRAM_RECEIVE_MODE = "webhook"` и непустого `TELEGRAM_WEBHOOK_SECRET` выполните из корня серверной установки (замените адрес своим реальным публичным HTTPS-доменом):

```bash
# Укажите собственный HTTPS-адрес, затем проверьте статус регистрации.
php bin/bot.php webhook set 'https://bot.example.org/webhook.php'
php bin/bot.php webhook info
```

Адрес для `set` должен использовать публичное DNS-имя и HTTPS на порту 443, 80, 88 или 8443; учётные данные, query и fragment не допускаются. При успехе `set` выводит «Webhook зарегистрирован.». `info` подтверждает регистрацию, количество ожидающих обновлений и состояние ошибок, **но не выводит зарегистрированный URL и не сверяет его с введённым адресом**.

После проверки можно включать cron. Для снятия регистрации используйте:

```bash
# Удалите регистрацию без очистки очереди и проверьте результат.
php bin/bot.php webhook delete
php bin/bot.php webhook info
```

После `delete` ожидается «Webhook удалён. Ожидающие обновления сохранены.», а затем «Webhook не зарегистрирован.». `info` и `delete` требуют только корректного токена бота, поэтому доступны и при выбранном `polling`; SQLite, профиль и настройки ИИ для этих команд не нужны. Не создавайте временные PHP-скрипты с самостоятельными вызовами Bot API.

## Запустите обработку через cron

Добавьте запуск раз в минуту от назначенного пользователя. Замените оба абсолютных пути на свои:

```cron
# Ежеминутный запуск; замените оба абсолютных пути.
* * * * * /absolute/path/to/php8.5 /absolute/path/to/project/bin/bot.php work-once
```

Рабочий каталог cron несущественен для приложения: [CLI-точка входа](../../bin/bot.php) определяет пути по своему расположению. Вывод cron направляйте только в закрытый журнал или почту администратора, не в публичный каталог.

Команда берёт общую блокировку `var/bot.lock`, восстанавливает прерванные попытки и выполняет до 10 порций обработки. Через 20 секунд новые порции не начинаются, но уже начатый запрос может выполняться до `AI_REQUEST_TIMEOUT_SECONDS` (30–1800 секунд). Занятый воркер приводит к пропуску следующего запуска cron, а не к параллельной оценке. Поведение задаёт [`BotRunner::workOnce()`](../../src/Application/BotRunner.php).

Отправьте боту небольшой вымышленный текст. Сначала ожидайте «Вакансия сохранена.», затем после запуска cron — уведомление начала анализа и итог. Подтверждение и уведомление начала могут не прийти при сетевом сбое; сохранённое сообщение от этого не исчезает.

## Приём и ошибки доставки

[`WebhookReceiver`](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/src/Application/WebhookReceiver.php) проверяет `X-Telegram-Bot-Api-Secret-Token` до разбора JSON и открытия БД. Обновление, сообщение и задание сохраняются одной транзакцией. HTTP 204 возвращается после записи данных в SQLite. Повторная доставка того же `update_id` не создаёт новое задание. Обновления могут приходить не по порядку.

| HTTP-код | Действие |
| --- | --- |
| 400 | Проверить формат JSON и обязательные поля запроса |
| 403 | Сверить секрет в INI и регистрации webhook, передачу заголовка до FPM |
| 405 | Использовать POST; GET годится только для проверки отказа |
| 413 | Проверить размер тела: предел 256 КиБ |
| 415 | Нужен `Content-Type: application/json` |
| 503 | Проверить режим, конфигурацию, автозагрузчик Composer, существование БД и права SQLite |

SQLite ожидает блокировку до 5 секунд. Ошибка сохранения приводит к 503, чтобы Телеграмм мог повторить доставку; такие повторы ограничены, поэтому устраняйте сбой своевременно. Подтверждение отправляется после успешной записи в SQLite. Если это же обновление придёт повторно, новое задание не создаётся. [Как устроены повторы](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/docs/guides/message-processing.md).

Для уведомления начала анализа предусмотрена одна попытка на вакансию. Готовая оценка сохраняется до отправки и повторно не рассчитывается при ошибке доставки. Лимит `AI_MAX_ATTEMPTS` применяется отдельно к анализу и доставке. Окончательно неудачные задания автоматически заново не создаются. Подробнее — [форматы и состояния результата](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/docs/reference/analysis-result.md).

## Переключение режимов

**С локального приложения на сервер:**

1. Остановите мониторинг и завершите `identify`, если он выполняется. Дождитесь окончания обработки.
2. При остановленных процессах перенесите `config/bot.ini`, профиль и весь `var/`, включая существующую SQLite-БД, на сервер. Не запускайте обе копии с одним токеном и разными данными.
3. Настройте PHP-FPM, HTTPS, права доступа и расписание cron, но пока не включайте расписание и не регистрируйте webhook. Убедитесь, что CLI и FPM используют одну БД.
4. Выберите `TELEGRAM_RECEIVE_MODE = "webhook"` и задайте секрет. Для подготовки схемы БД выполните `php bin/bot.php work-once` от пользователя cron. **Это не диагностический dry-run:** при наличии ожидающих заданий команда также может вызвать ИИ и отправить сообщения. Если обработка очереди пока нежелательна, не запускайте `work-once` лишь ради проверки настроек.
5. Зарегистрируйте свой HTTPS-адрес командой `php bin/bot.php webhook set 'https://bot.example.org/webhook.php'`, заменив пример своим адресом. Проверьте `webhook info` и включите cron.

Во время переключения используйте одну актуальную копию данных. Если Telegram уже подтвердил или удалил обновления, перенос БД не восстановит их.

**С сервера на локальный запуск:**

1. Отключите cron и дождитесь завершения активного воркера.
2. Выполните `php bin/bot.php webhook delete` (команда сохраняет ожидающие обновления) и через `php bin/bot.php webhook info` убедитесь, что выведено «Webhook не зарегистрирован.».
3. Дождитесь завершения уже начавшихся запросов к PHP-FPM и отключите публичный обработчик webhook, чтобы он больше не записывал в БД.
4. При остановленных обработчиках сохраните ту же БД и приватные файлы; при переносе скопируйте весь `var/`.
5. Задайте `TELEGRAM_RECEIVE_MODE = "polling"` и запустите локальное приложение или `php bin/bot.php run` из исходников.

Не очищайте курсор, таблицу полученных обновлений или сообщения вручную. При длительном простое polling самостоятельно сбрасывает недоверенный исходящий `offset` без удаления данных. `run` и `identify` недоступны при выбранном `webhook`; переключение значения в INI само по себе не регистрирует и не удаляет webhook: для этого нужны команды `webhook set` и `webhook delete`.

При неполадках воспользуйтесь [локальными подсказками](local-gum.md#если-что-то-не-работает) или [расширенным руководством](https://github.com/yaleksandr89/telegram-vacancy-monitor/blob/master/docs/guides/troubleshooting.md).
