# Устранение неполадок

Начните с «Проверить готовность» в локальном приложении и откройте «Подробнее» для отмеченной категории. Проверка не обращается к Телеграмму или ИИ, не проверяет содержимое профиля и не записывает SQLite. Успех означает, что локальные предпосылки готовы; подключение проверяется отправкой тестового текста работающему боту.

Тексты экранов находятся в [сообщениях интерфейса](../../src/ui/windows/messages.json), проверки и категории ошибок — в [`inspect.php`](../../src/ui/windows/inspect.php). При обращении за помощью передавайте категорию и код завершения, ОС и способ запуска, без токенов и содержимого личного профиля.

## Приложение не открывается

| Симптом | Что сделать |
| --- | --- |
| «Файлы приложения отсутствуют или повреждены» | Заново распаковать доверенный архив в отдельную папку; сохранить структуру и перенести только свои INI, профиль и `var/` |
| «Нужен интерактивный терминал» | Запустить из обычного терминала без перенаправления ввода, вывода и ошибок |
| «Среда PHP приложения неполна или устарела» | Проверить, что выбран архив своей ОС и архитектуры, а `runtime/` распакован полностью |
| Не удалось подготовить запуск и диагностику | Проверить доступность системного временного каталога и права запуска файлов |
| Windows запрещает скрипт | Проверить действующую организационную политику PowerShell; согласовать запуск с администратором |
| macOS блокирует загруженное приложение | Проверить происхождение архива и причину в настройках безопасности macOS |

При повреждении файлов восстановите архив целиком: [исполняемый файл](../../src/launcher/main.go) сверяет публичные файлы с манифестом. Порядок переустановки с сохранением данных описан в [локальном руководстве](local-gum.md#данные-и-обновление).

Для установки из исходников требуются PHP `^8.5`, расширения из [`composer.json`](../../composer.json) и созданный автозагрузчик Composer. Сообщение об отсутствии `vendor/autoload.php` устраняется установкой зависимостей по `composer.lock`; оно не требует изменения профиля или SQLite.

## Конфигурация или профиль не готовы

- Создайте `config/bot.ini` по [образцу](../../config/bot.example.ini). Убедитесь, что редактор не добавил расширение `.txt`.
- Проверьте кавычки и имена ключей. Для списков предфильтра нужны повторяемые ключи с `[]`.
- Укажите токен бота, Telegram ID своего аккаунта в `TELEGRAM_ALLOWED_USER_ID`, адрес и идентификатор модели. Для облачной модели также нужен ключ API.
- Создайте оба файла: `config/profile/local/candidate.md` и `config/profile/local/instructions.md`.
- Сохраните их как обычные непустые файлы UTF-8, без символических ссылок, каждый до 32 768 байт и 16 000 символов. Табуляция и переводы строк допустимы, другие управляющие символы — нет.

Если проверка готовности пропускает файл, но запуск отклоняет его, проверьте кодировку, число символов и содержимое: меню проверяет только доступность и размер файла. Точные ограничения описаны в [руководстве профиля](../../config/profile/README.md), параметры — в [справочнике конфигурации](../reference/configuration.md).

После правок перезапустите локальный мониторинг. На сервере новые файлы прочитает следующий `work-once`.

## Не удаётся получить ID

Отправьте `/start` именно тому боту, чей токен записан в INI, затем нажмите «Проверить сейчас» ещё раз или выполните `php bin/bot.php identify` из исходников. Поиск не опрашивает Телеграмм автоматически и не подтверждает обновления.

Проверьте, что другой процесс не получает сообщения этого бота и вебхук отключён. Если найдено несколько ID, используйте свой. Для первого определения ID профиль и подключение ИИ не требуются. См. [настройку бота](telegram-bot.md#узнайте-свой-id).

## Авторизация, доступ и конфликт приёма

| Ошибка | Причина и действие |
| --- | --- |
| Bot API 401, авторизация отклонена | Проверить актуальность токена BotFather; после перевыпуска заменить его в INI |
| Bot API 403, чат недоступен | Убедиться, что вы начали чат с ботом, не заблокировали его и указали Telegram ID своего аккаунта |
| Bot API 409 или конфликт polling | Остановить вторую копию; проверить webhook через `getWebhookInfo` |
| «Бот уже запущен либо недоступна блокировка» | Проверить оставшийся процесс и права на `var/bot.lock`; не удалять файл блокировки для обхода работающего процесса |
| Выбран webhook, локальный запуск запрещён | Использовать серверный `work-once` либо выполнить полное переключение на polling |
| Bot API 429 | Подождать перед повтором; не запускать несколько получателей |

Бот может получать сообщения либо через `getUpdates`, либо через вебхук. Замена настроек не отменяет регистрацию вебхука. Для возврата используйте `deleteWebhook` с `drop_pending_updates = false`, проверку пустого URL и [порядок переключения](vds-webhook.md#переключение-режимов).

Режим `identify --json`, используемый меню, намеренно возвращает общую ошибку без исходного исключения. Категория иногда остаётся неизвестной; это не доказательство конкретной сетевой или конфигурационной причины.

## Ошибка сети или TLS

Для обращения к Телеграмму проверьте DNS, доступность HTTPS к `api.telegram.org`, системную дату и доверие сертификатам. У локального архива должен сохраняться комплектный `runtime/cacert.pem`. Не отключайте TLS-проверку для обхода ошибки.

Для ИИ отдельно проверьте, что сервер запущен, модель загружена, адрес доступен именно из среды приложения и порт разрешён межсетевым экраном. `127.0.0.1` внутри WSL, виртуальной машины или VDS не указывает на другой компьютер. Используйте доступный частный IPv4 для режима `local`.

AI-транспорт не использует прокси и не следует HTTP-перенаправлениям. Укажите конечный базовый адрес API. Сетевые пределы задаёт [`CurlAiTransport`](../../src/Analysis/Http/CurlAiTransport.php).

## Вакансия сохранена, но оценки нет

1. Убедитесь, что локальный мониторинг продолжает работать. На сервере проверьте запуск cron, его пользователя, абсолютные пути PHP и проекта, закрытый вывод команды.
2. Учтите очередь и время ответа: запросы выполняются последовательно, на сервере начало обработки зависит от cron.
3. Проверьте модель и формат API. Адрес задаётся без `/chat/completions`; приложение добавляет этот путь само.
4. Для медленной модели увеличьте `AI_REQUEST_TIMEOUT_SECONDS` с `180` до `300` или `600` и перезапустите обработку. Диапазон — 30–1800.
5. Если пришло «Не удалось обработать», исправьте причину перед следующей проверкой: исходная вакансия остаётся в БД, но окончательно неудачное задание автоматически не возобновляется.

На сервере успешный приём webhook ещё не означает готовность ИИ: HTTP-обработчик не загружает профиль и не вызывает модель. Команда `work-once` должна успешно пройти собственную настройку.

Если нужно уточнить этап сбоя, откройте **свою** `var/vacancies.sqlite` локальным SQLite-клиентом только для чтения и посмотрите состояния без текста вакансий:

```sql
SELECT message_id, analysis_status, analysis_error, analysis_attempts,
       delivery_status, delivery_error, delivery_attempts
FROM analysis_jobs
ORDER BY message_id DESC
LIMIT 10;
```

Состояния хранятся в [`SqliteAnalysisRepository`](../../src/Storage/SqliteAnalysisRepository.php). Не меняйте счётчики и статусы вручную. Не публикуйте БД; если передаёте диагностическую выборку, уберите личные идентификаторы.

## Модель возвращает ошибку или неподходящий формат

| Категория в состоянии анализа | Что проверить |
| --- | --- |
| `http_401`, `http_403` | Ключ и права доступа к выбранной модели |
| `http_404` | Базовый путь API и идентификатор модели по документации провайдера |
| `http_429`, `http_5xx` | Лимиты и доступность провайдера; такие ошибки допускают повтор |
| `timeout` | Время ожидания, загрузку и скорость модели |
| `invalid_response` | Оболочку Chat Completions: строковый `choices[0].message.content`, без вызовов инструментов |
| `invalid_output` | Ровно один JSON-объект с обязательными полями и допустимыми значениями, без Markdown-обрамления |
| `response_size` | Слишком длинный ответ API: предел 65 536 байт |
| `vacancy_size_or_encoding` | Корректный UTF-8 текста вакансии и предел 65 536 байт |
| `transport` | Соединение, TLS и сетевой доступ к серверу ИИ |

`http_5xx` в таблице обозначает семейство категорий с конкретным кодом, например `http_503`. Допустимость повтора зависит от причины, а не только от числа оставшихся попыток. Схема и дополнительные ограничения строк приведены в [справочнике результата](../reference/analysis-result.md). Для сравнения параметров используйте [руководство модели](ai-models.md).

## Оценка есть в БД, но её нет в чате

Проверьте, что бот не заблокирован и чат доступен. Отправка готового результата имеет собственные попытки и не вызывает модель повторно. При `delivery_status = failed` результат остаётся в БД, отдельное уведомление об ошибке доставки не отправляется. Команды ручной повторной доставки нет.

Уведомление начала анализа имеет только одну попытку, поэтому его отсутствие не означает потерю задания. После аварии между отправкой и сохранением подтверждения итоговое сообщение может прийти повторно. Эти случаи объяснены в [процессе обработки](message-processing.md).

## SQLite или webhook недоступны

Проверьте свободное место, чтение и запись БД, права на каталог `var/` для журналов SQLite. На сервере CLI и FPM должны работать с одной БД; проверьте доступ от обеих учётных записей. Ожидание блокировки SQLite ограничено 5 секундами.

Webhook возвращает 503 при неготовности или ошибке хранилища и 403 при неправильном секрете. Сверьте секрет в INI и `setWebhook`, затем проверьте `getWebhookInfo`. Полный разбор HTTP-кодов, подготовка БД и права описаны в [серверном руководстве](vds-webhook.md).

Не удаляйте `var/`, БД или локальную конфигурацию ради «чистого» запуска. При обновлении сохраняйте приватные файлы и состояние очереди.
