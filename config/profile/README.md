# Настройка профиля и анализа

В этом каталоге находятся инструкции по настройке анализа сообщений, которые вы отправляете боту. Приложение сохраняет исходный текст, оценивает его с помощью выбранной языковой модели и присылает результат в Телеграмм.

Личные сведения и рабочие инструкции для модели хранятся отдельно от исходного кода. Их можно менять без коммитов и изменений PHP-файлов.

## 1. Подготовьте два файла

Создайте каталог `config/profile/local/`, если его ещё нет. Внутри должны находиться два файла в кодировке UTF-8:

- **`candidate.md`** — информация о кандидате: опыт, навыки, предпочтения, условия работы и ограничения, которые важно учитывать.
- **`instructions.md`** — задание для языковой модели: что именно анализировать, как оценивать сообщения и что учитывать при выборе вердикта.

Для `instructions.md` используйте образец `config/profile/instructions.example.md`. Его можно скопировать в локальный каталог и изменить под свои задачи. Для обоих файлов подходит обычный Markdown; специальные заголовки не обязательны.

Весь каталог `local/` исключён из Git, включая вложенные файлы и резервные копии. Не добавляйте его в репозиторий принудительно. Если в профиле есть личные данные, помните, что при использовании облачной модели они могут быть отправлены выбранному сервису.

Профиль и инструкции загружаются при запуске бота. После изменения любого из этих файлов перезапустите приложение. Уже сохранённые результаты автоматически не пересчитываются.

Если обязательный файл отсутствует, пуст или не может быть прочитан, бот сообщит об ошибке **до начала приёма сообщений**. Команда `identify` остаётся доступной без этих файлов.

Размер каждого файла ограничен 32 КБ исходного текста и 16 000 символов. Файлы должны содержать корректный UTF-8; служебные управляющие символы не допускаются, кроме обычных переводов строк и табуляции.

## 2. Выберите языковую модель

Подключение настраивается в приватном `config/bot.ini`. Список параметров и примеры приведены в `config/bot.example.ini`.

**Если модель работает на вашем компьютере** (например, через LM Studio, Ollama или Unsloth Desktop), укажите:

- `AI_PROVIDER_LOCATION = "local"`;
- `AI_BASE_URL` — адрес локального API-сервера;
- `AI_MODEL` — идентификатор запущенной модели;
- `AI_API_KEY` — ключ, если он требуется вашим сервером; в остальных случаях можно оставить пустым.

Для LM Studio типичный адрес при запуске на том же компьютере: `http://127.0.0.1:1234/v1`. Если PHP работает в WSL, а модель запущена в Windows, может потребоваться другой локальный сетевой адрес. Адрес зависит от ваших сетевых настроек.

**Если используете облачную модель** (например, через OpenRouter), укажите:

- `AI_PROVIDER_LOCATION = "cloud"`;
- `AI_BASE_URL` — HTTPS-адрес API, предоставленный выбранным сервисом;
- `AI_MODEL` — идентификатор модели из его документации;
- `AI_API_KEY` — ключ, созданный в кабинете сервиса.

При облачном анализе выбранному сервису отправляются текст сообщения, профиль и инструкции для модели. Учитывайте это, если работаете с личной информацией или непубличными объявлениями. Достаточно выбрать нужный режим и заполнить его параметры: дополнительного флага подтверждения нет.

Приложение использует OpenAI-совместимый метод `/chat/completions`. Убедитесь, что выбранный сервер и модель поддерживают его и возвращают обычный JSON-ответ. Подключение конкретной модели проверяется отдельно; наличие её названия в этой инструкции не означает, что она уже протестирована.

## 3. Необязательная быстрая проверка сообщений

По умолчанию **все сохранённые сообщения передаются языковой модели**. При необходимости можно настроить быстрый отказ для точно известных коротких сообщений, которые не требуют AI-анализа.

В `config/bot.ini` для этого используются повторяемые параметры:

```ini
AI_PREFILTER_EXACT_REJECT_LINES[] = "Только ночная смена."
AI_PREFILTER_AMBIGUITY_TERMS[] = "обсуждается"
```

Первый параметр задаёт **полный текст сообщения**, при точном совпадении с которым анализ пропускается. Второй перечисляет слова, при наличии которых автоматический отказ отменяется. Регистр букв учитывается при точном сравнении, но не при поиске слов неоднозначности.

Это простой механизм точного сравнения, **не анализ смысла текста**. Он не отсеивает длинную вакансию только потому, что внутри встретилась похожая фраза. Если есть дополнительные условия, переносы строк или сомнения, сообщение передаётся модели. Персональные ограничения по городам, зарплате и технологиям лучше записывать в локальные инструкции и профиль, а не в исходный код.

Настраивать эти параметры необязательно. Не используйте в них регулярные выражения или PHP-код: значения воспринимаются как обычный текст.

## 4. Что вы получите от бота

Для каждой обработанной вакансии бот отправляет один из вердиктов: **«Откликаться»**, **«Погранично»** или **«Пропустить»**. В ответе также показываются краткое обоснование, важные условия, риски и вопросы для уточнения.

Если в объявлении есть подходящая ссылка, бот покажет её. Ссылка, просто найденная в тексте, будет отмечена как **непроверенная**. Если данные пересылки позволяют сопоставить ссылку с исходной публикацией, бот сообщит об этом отдельно. Приложение **не открывает ссылки и не загружает сайты автоматически**.

Длина ответа ограничена возможностями Телеграмма. При необходимости бот сокращает второстепенные списки, сохраняя вердикт, основные условия и ссылку. Эмодзи и другие символы Unicode учитываются при проверке длины сообщения.

## 5. Если модель или Телеграмм временно недоступны

`AI_REQUEST_TIMEOUT_SECONDS` в приватном `config/bot.ini` задаёт предел ожидания одного AI-запроса: целое число от 30 до 1800 секунд. По умолчанию, в том числе без ключа, используется 180 секунд. Каждая повторная попытка имеет собственный предел ожидания.

Если медленная локальная модель не успевает, временно укажите `AI_REQUEST_TIMEOUT_SECONDS = "600"` (или `"300"`) и перезапустите бота. Коммит и push не нужны. Даже 300 секунд могут оказаться недостаточными для объёмного запроса. Для разового медленного эксперимента можно также поставить `AI_MAX_ATTEMPTS = "1"`, чтобы не ждать три долгие попытки.

Приложение сохраняет исходное сообщение и состояние обработки в SQLite. По умолчанию для анализа и отправки ответа предусмотрено **до трёх попыток на каждый этап**, включая первую. Количество попыток настраивается параметром `AI_MAX_ATTEMPTS` (от 1 до 5).

Если анализ завершился, но отправка результата не удалась, готовая оценка остаётся сохранённой. Повторная отправка **не запускает анализ заново**. После исчерпания попыток сохраняется статус «Не удалось доставить»; при неудаче самого анализа — «Не удалось обработать».

После перезапуска бот продолжает незавершённую работу. В редких случаях, когда внешний сервис уже выполнил запрос, но приложение не успело сохранить ответ, запрос или уведомление может повториться.

Бот обрабатывает ожидающие сообщения небольшими порциями, регулярно возвращаясь к получению новых сообщений. Пока модель отвечает на запрос, обработка этого запроса выполняется последовательно в том же процессе.

## 6. Локальные проверки

Из корня проекта в Linux или WSL можно выполнить:

```bash
composer lint   # Проверка синтаксиса PHP
composer test   # Автономные тесты без реальных API
composer check  # Проверка Composer, синтаксиса и тестов
```

Эти команды используют искусственные данные и не проверяют реальное подключение к Телеграмму или выбранной модели. Для живой проверки сначала настройте модель, затем отправьте боту тестовое сообщение и проверьте результат. Версию приложения для запуска моделей, название модели и результат проверки стоит записать отдельно для будущей документации.

Корневой `README.md` проекта будет оформлен на отдельном этапе; этот файл посвящён только настройке анализа.
